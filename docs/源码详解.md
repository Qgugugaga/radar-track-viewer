## 0. 页面在做什么

一句话：把 303 个经纬度点画到一个"可以缩放、可以拖动"的直角坐标系里。

功能清单：

1. 初始视野自动框住所有点（外接矩形恰好展现）
2. 滚轮缩放，以光标为中心，无固定中心点
3. 按住左键拖空白处平移（范围受限，拖不丢数据）
4. 按住某个点拖动 = 修改它的经纬度，连线实时跟随
5. 一键恢复坐标 / 恢复视野
6. 蓝白配色、无背景

学习本文时，把「**数据**」「**坐标系**」「**渲染**」「**交互**」四个词记在心里，整份代码就是围绕它们组织的。

## 1. 项目是怎么跑起来的

### 1.1 文件职责

| 文件 | 作用 |
|---|---|
| `index.html` | 网页骨架，只有一个 `<div id="app">` 挂载点 |
| `src/main.js` | 入口：创建 Vue 应用并挂载到 `#app` |
| `src/style.css` | 全局基础样式（页面铺满、字体、无滚动条） |
| `src/App.vue` | 页面全部逻辑：数据、画布、交互、面板 |

（`public/track-data.csv` 是数据文件，`vite.config.js` 是开发服务器配置。）

### 1.2 main.js 逐行

```js
import { createApp } from 'vue'   // ① 从 vue 包引入"创建应用"的函数
import App from './App.vue'       // ② 引入根组件
import './style.css'              // ③ 引入全局样式（Vite 会处理成网页样式）

createApp(App).mount('#app')      // ④ 创建应用，把 App 组件渲染进 #app
```

`createApp(App)` 创建一个 Vue 应用实例；`.mount('#app')` 把 index.html 里那个空的 `<div id="app">` 替换成我们整个页面。

### 1.3 `<script setup>` 语法糖

App.vue 第一行是 `<script setup>`。它的含义：这个 `<script>` 里声明的所有变量、函数，`<template>` 里都能**直接**用，不用写 `export default { data() {...} }` 之类的样板，Vue 编译时会帮你处理好。

```html
<script setup>
const showLine = ref(true)      // 模板里直接写 showLine 就能用
function resetCoords() { ... }  // 模板里直接 @click="resetCoords"
</script>
```

## 2. 数据：页面的"记忆"

### 2.1 ref 与 reactive（入门必懂）

```js
const points = ref([])              // 数组：303 个点
const loaded = ref(false)           // 数据加载完没有
const showLine = ref(true)          // 连线开关
const view = reactive({ s: 1, ox: 0, oy: 0 })   // 视图窗口三要素
```

- `ref(x)`：把值包一层。在 `<script>` 里读写要 `.value`（如 `points.value`）；在模板里 Vue 自动解包，直接写 `points`。
- `reactive(obj)`：整个对象变成响应式，改 `view.s = 2` 就会触发依赖它的代码更新。
- 为什么 points 用 ref 而不是 reactive？因为后面要**整体替换**：`points.value = parseCsv(...)`。ref 的 `.value` 允许换整个数组，reactive 不适合整体替换。

**核心概念：响应式 = 数据变了，画面自动跟着变。** 你在页面上拖动一个点，代码里其实只做了一件事——`p.lon = 新值`。Vue 感知到这个变化，通知画布重画。整个页面没有一处"手动刷新画面"的样板代码。

### 2.2 每个点的结构：lon0/lat0 的妙用

```js
{ t: '9:15:27', lon: 123.0944143, lat: 39.43693225, lon0: 123.0944143, lat0: 39.43693225 }
```

- `lon / lat`：当前坐标（可被拖动修改）
- `lon0 / lat0`：备份的初始坐标，**永不修改**

「恢复坐标」按钮做的事情就是：

```js
function resetCoords() {
  for (const p of points.value) {
    p.lon = p.lon0
    p.lat = p.lat0
  }
}
```

这也顺带回答了「为什么拖动一个点、其他点不动」：拖动时只改了**那一个点**的 `lon/lat`，别的点根本没被动过；而连线之所以跟着变，是因为它每帧都按最新坐标重画（见 4.6 节）。

### 2.3 computed：自动更新的"计算值"

```js
const zoomRatio = computed(() => (fitS.value > 0 ? view.s / fitS.value : 1))
const scaleText = computed(() => {
  if (!loaded.value) return '—'
  const deg = 1 / view.s
  return `1 px ≈ ${deg >= 0.001 ? deg.toFixed(3) : deg.toFixed(6)}° · ${zoomRatio.value.toFixed(2)}×`
})
```

computed 里用到的响应式数据一变，它就会自动重算（并且有缓存）。页面面板上的「1 px ≈ 0.001° · 2.4×」就是 `scaleText` 算出来的；你缩放一下，它自己就更新，不需要任何额外代码。

## 3. 核心：经纬度 → 屏幕像素（最重要的一节）

### 3.1 想象一个"取景框"

把经纬度世界想成一张无限大的坐标纸，浏览器窗口是放在纸上的一个**取景框**。三个数字描述取景框的位置（定义在 `view` 里）：

```js
const view = reactive({ s: 1, ox: 0, oy: 0 })
```

| 变量 | 含义 |
|---|---|
| `s` | 比例尺：1 度经度在屏幕上占多少像素 |
| `ox` | 取景框**左边缘**所在的经度 |
| `oy` | 取景框**下边缘**所在的纬度 |

用左下角而不是中心描述窗口，是因为需求规定原点在左下角，这样写数学上最顺手。

### 3.2 换算公式（正反都要背下来）

```js
// 正：经纬度 → 屏幕（数学坐标，y 向上为正）
x = (lon - view.ox) * view.s
y = (lat - view.oy) * view.s

// 反：屏幕 → 经纬度（拖动点、缩放锚点、命中检测都要用）
lon = view.ox + x / view.s
lat = view.oy + y / view.s
```

怎么理解？`(lon - ox)` 是"这个点离取景框左边缘多少度"，乘上 `s`（像素/度）就得到像素距离。反推公式就是把它倒过来解方程。

### 3.3 Canvas 的 y 轴是反的，画的时候要翻一下

网页坐标系原点在**左上角**、y 向下；我们的数学坐标系原点在**左下角**、y 向上。所以凡是"画"的代码都要翻转一次：

```js
const x = (p.lon - view.ox) * view.s
const y = H - (p.lat - view.oy) * view.s   // H - y 完成翻转
ctx.arc(x, y, r, 0, Math.PI * 2)
```

`H` 是画布高度。**记住这条纪律**：所有"画"的代码用 `H - y`；所有"算"的代码（命中检测、拖动换算）用数学坐标。混用必出 bug，这是 Canvas 可视化最常见的坑。

### 3.4 为什么 x 轴、y 轴永远"钉"在页面边缘

看 `drawAxes`：

```js
ctx.strokeStyle = C.axis
ctx.lineWidth = 1.5
ctx.beginPath()
ctx.moveTo(0, H - 0.75)
ctx.lineTo(W, H - 0.75)   // x 轴：固定在页面下边缘，与 view 无关
ctx.stroke()
ctx.beginPath()
ctx.moveTo(0.75, 0)
ctx.lineTo(0.75, H)       // y 轴：固定在页面左边缘，与 view 无关
ctx.stroke()
```

轴线画在**固定像素位置**，完全不看 `view`；缩放/平移只改变网格线、刻度文字和点的位置。这就是需求「缩放只改变轴比例与点的大小，不改变页面坐标系的展示大小」的实现原理——简单到只有两行线。

## 4. 渲染：Canvas 画出一切

### 4.1 为什么用 Canvas

303 个点如果用 DOM/SVG 元素，拖拽时每个元素都要单独移动、单独重排，容易卡。Canvas 的思路是"**每帧把整张图重画一遍**"：几百个圆的绘制对浏览器来说微不足道，天然保证丝滑，而且点的位置、连线、高亮都在同一处代码里控制。

### 4.2 高清屏适配（dpr）

```js
dpr = Math.max(1, window.devicePixelRatio || 1)
c.width = Math.round(W * dpr)       // 画布实际分辨率放大 dpr 倍
c.height = Math.round(H * dpr)
// 每次绘制开头：
ctx.setTransform(dpr, 0, 0, dpr, 0, 0)   // 之后仍用 CSS 像素思考，坐标自动放大
```

不这么做，在 2 倍缩放的笔记本屏幕上画面会发虚。`W`、`H` 存的是 CSS 像素（布局尺寸），绘制坐标全用 CSS 像素，`setTransform` 负责放大到物理像素。

### 4.3 draw() 的分层顺序

```js
function draw() {
  ctx.clearRect(0, 0, W, H)        // ① 清屏（白底）
  drawGrid(ctx)                    // ② 网格和刻度（最底）
  if (showLine.value && points.value.length > 1) drawTrack(ctx)  // ③ 连线
  drawPoints(ctx)                  // ④ 点（压住连线）
  drawAxes(ctx)                    // ⑤ 坐标轴（压住网格）
}
```

Canvas 后画的盖住先画的，调用顺序就是图层顺序。注意连线的开关 `showLine` 在这里生效：关掉开关 → 跳过 drawTrack → 重画 → 线没了。

### 4.4 网格刻度：1-2-5 取整算法

刻度间隔不能乱取，人类习惯 1、2、5、10、20、50… 这种步长。`niceStep` 把"想要的像素间距"翻译成"合适的度数步长"：

```js
function niceStep(raw) {
  const p = Math.pow(10, Math.floor(Math.log10(raw)))  // 数量级：0.017 → 0.01
  const n = raw / p                                    // 归一化：1.7
  return (n >= 5 ? 5 : n >= 2 ? 2 : 1) * p             // 落到 1 / 2 / 5 上
}
```

例：初始适配时 `raw = 90 / view.s ≈ 0.017` 度（希望每 90px 一条网格线）。`log10(0.017) ≈ -1.77`，floor 得 -2，`p = 0.01`；`n = 1.7`（在 1 和 2 之间）→ 取 1 → `step = 0.01°`。若 `n` 是 2.5 就取 2（0.02°），若是 6 就取 5（0.05°）。

配套的小数位公式：

```js
const decLon = Math.max(0, Math.min(9, Math.ceil(-Math.log10(stepLon) - 1e-9)))
```

step = 0.01 → `-log10(0.01) = 2` → 刻度显示 2 位小数（`123.09°`）；step = 1 → 0 位（`123°`）。`- 1e-9` 是浮点误差保险丝（防止 step=1 时算出 0.9999… 导致多一位小数）。

### 4.5 画点：视口裁剪与高亮

```js
for (let i = 0; i < pts.length; i++) {
  const x = (p.lon - view.ox) * view.s
  const y = (p.lat - view.oy) * view.s
  // 屏幕外（含半径余量）的点直接跳过：
  if (x < -r0 - 4 || x > W + r0 + 4 || y < -r0 - 4 || y > H + r0 + 4) continue
  ...
}
```

放大 50 倍时大部分点都在屏幕外，`continue` 跳过它们，保证重绘永远轻快——这招叫**视口裁剪（culling）**。

被拖动的点最后单独画，并加两条指向坐标轴的虚线（参考线），帮用户读出它当前的经纬度；它的颜色是柔和橙色 `#fb923c`，与蓝色主色调区分。

### 4.6 连线为什么"自动"跟着变

`drawTrack` 每帧从 `points.value` **现取**坐标：

```js
for (let i = 0; i < pts.length; i++) {
  const x = (pts[i].lon - view.ox) * view.s
  const y = H - (pts[i].lat - view.oy) * view.s
  if (i === 0) ctx.moveTo(x, y)
  else ctx.lineTo(x, y)
}
```

拖动点 = 改数据 → 重画 = 连线自然跟着变。**没有"额外通知连线"的代码**——这就是"全量重绘"架构的简洁之处：任何数据变化都会自动反映到画面，因为你每帧都在重新读数据。

### 4.7 合帧调度 scheduleDraw

```js
function scheduleDraw() {
  if (!rafId) rafId = requestAnimationFrame(() => {
    rafId = 0
    draw()
  })
}
```

鼠标一帧内可能触发几十次 pointermove，但 `scheduleDraw` 保证一帧只画一次（下一次浏览器刷新时执行）。`rafId` 充当"已预约"标记，避免重复预约。既省电又丝滑。

## 5. 交互 1：滚轮缩放（光标为锚点）

### 5.1 "无固定中心点"的实现

需求：缩放不能围绕某个固定点（比如原点），而是**光标指着哪里，哪里就不动**。这就是常见地图的滚轮手感。

### 5.2 数学推导

缩放前，光标 `(cx, cy)` 处的经纬度是：

```js
const wx = view.ox + cx / view.s            // 经度（正推公式）
const wy = view.oy + (H - cy) / view.s      // 纬度（注意 y 翻转）
```

缩放后 `s` 变成 `sNew`，要求 `wx/wy` 仍在光标下，反解出新窗口位置：

```js
view.ox = wx - cx / sNew
view.oy = wy - (H - cy) / sNew
```

这就是 `zoomAt` 的全部魔法：

```js
function zoomAt(cx, cy, sNew) {
  sNew = Math.min(sMax(), Math.max(sMin(), sNew))   // 先把倍率夹在上下限内
  const wx = view.ox + cx / view.s
  const wy = view.oy + (H - cy) / view.s
  view.s = sNew
  view.ox = wx - cx / sNew
  view.oy = wy - (H - cy) / sNew
  clampView()      // 缩完顺手把窗口拉回合法范围（见第 6 节）
  scheduleDraw()
}
```

### 5.3 缩放上下限

```js
const sMin = () => Math.max(1e-3, fitS.value * 0.5)  // 最小：初始适配的一半
const sMax = () => fitS.value * 50                  // 最大：初始适配的 50 倍
```

`fitS` 是"恰好框住全部点"的比例尺（加载时算好）。50 倍时屏幕上大约只剩 1~2 个点，足够看清每个点，又不会放大到漫无边际；想改上限就改这一行的 `50`。

滚轮触发处：

```js
function onWheel(e) {
  e.preventDefault()                       // 阻止浏览器默认的页面滚动
  const f = Math.exp(-e.deltaY * 0.0016)  // 每格滚轮 ≈ 缩放 1.17 倍，指数曲线手感平滑
  zoomAt(e.offsetX, e.offsetY, view.s * f)
}
```

`e.preventDefault()` 必须配合 `{ passive: false }` 的事件注册（见 9.1 节），否则浏览器会忽略它。

## 6. 交互 2：平移与"拖不远"的边界

### 6.1 拖动换算

鼠标向右移动 dx 像素，世界要"跟着手走"：取景框左边缘应减小 `dx / s` 度：

```js
view.ox -= (x - lastX) / view.s
view.oy += (y - lastY) / view.s
```

（y 方向正负号和 x 相反，因为屏幕 y 向下、数学 y 向上。动手推一遍正推公式就明白。）

### 6.2 clampView：把窗口"关"在数据附近

早期版本可以无限制拖动，几下就能把整片数据拖到十万八千里外。修复 = 规定窗口**必须始终与"数据外接矩形 + 各边 25% 余量"相交**：

```js
const WORLD = { minLon: 0, maxLon: 0, minLat: 0, maxLat: 0 }  // 当前所有点的外接矩形

function updateWorldBounds() {
  // 遍历所有点求 min/max（初值 Infinity / -Infinity 是求极值惯用技巧）
  ...
}

function clampView() {
  if (!points.value.length || W <= 0 || H <= 0) return
  updateWorldBounds()
  const spanLon = Math.max(WORLD.maxLon - WORLD.minLon, 1e-6)
  const padLon = spanLon * 0.25              // 各边 25% 余量
  // 窗口 [ox, ox + W/s] 必须碰到 [minLon - pad, maxLon + pad]：
  view.ox = Math.min(Math.max(view.ox, WORLD.minLon - padLon - W / view.s), WORLD.maxLon + padLon)
  view.oy = Math.min(Math.max(view.oy, WORLD.minLat - padLat - H / view.s), WORLD.maxLat + padLat)
}
```

三个要点：

1. **夹逼写法** `Math.min(Math.max(x, 下界), 上界)`：先把 x 抬到下界，再压到上界，结果必然落区间内。
2. **边界随点动态变化**：`updateWorldBounds` 每次现算。哪怕你把某个点拖到很远，边界立刻跟着扩大，那个点永远可见、可被拖回，不会"丢"。
3. **调用时机**：平移、缩放（zoomAt）、捏合、窗口尺寸变化后都会调用——所有会改变视野的入口统一收口。

为什么下限是 `minLon - pad - W/s` 而不是 `minLon - pad`？因为窗口右边缘是 `ox + W/s`，窗口要"碰到"数据区，最左允许 `ox = minLon - pad - W/s`（此时右边缘刚好挨着数据区左缘）。缩放越大 `W/s` 越小，可拖范围自然收窄——这就是"放大倍率与可拖范围"的平衡点。

## 7. 交互 3：拖动数据点改坐标

### 7.1 hitTest：找到鼠标下的点

```js
function hitTest(cx, cy) {
  const r = Math.max(pointRadius() + 2, 8)  // 命中半径：点半径 + 2px，至少 8px（手指也点得中）
  let best = -1
  let bestD = Infinity
  for (let i = 0; i < pts.length; i++) {
    const dx = (p.lon - view.ox) * view.s - cx
    const dy = (p.lat - view.oy) * view.s - (H - cy)
    const d = dx * dx + dy * dy
    if (d <= r * r && d < bestD) { bestD = d; best = i }   // 多个点重叠时取最近
  }
  return best
}
```

303 个点一个个算距离？对，完全够快——普通电脑每秒能算上千万次这种简单数学，别被"循环 303 次"吓到。

### 7.2 Pointer Events：一支笔管全部设备

`pointerdown / pointermove / pointerup` 同时覆盖鼠标与触屏。两个关键动作：

- `e.button !== 0`：只响应左键（单指触摸 button 也是 0）；
- `c.setPointerCapture(e.pointerId)`：按下后即使拖出画布，事件仍持续送到画布，拖动不中断。

按下时决定模式（onPointerDown）：

```js
const hit = hitTest(e.offsetX, e.offsetY)
if (hit >= 0) { dragged.value = hit }   // 按在点上 → 拖点模式
else { panning = true }                 // 按在空白 → 平移模式
```

`e.offsetX / e.offsetY` 是相对画布的坐标——比 `clientX` 省去手动换算。

### 7.3 拖动 = 反向换算 + 实时写回

```js
if (dragged.value >= 0) {
  const p = points.value[dragged.value]
  p.lon = view.ox + x / view.s          // 屏幕坐标 → 经纬度（反推公式）
  p.lat = view.oy + (H - y) / view.s
  moveTip(x, y)                         // 提示框跟着光标
}
```

改的是**数据**，画面每帧重绘，于是：点跟着光标走、连线跟着点变、提示框里经纬度实时跳动（还显示原值对比），其他点纹丝不动——一条 `p.lon = ...` 全搞定。

### 7.4 两个恢复按钮

- **恢复坐标**：`p.lon = p.lon0`（数据回滚，视野不动）
- **恢复视野**：`fitView()`——重算"恰好框住全部点"的比例尺与窗口：

```js
function fitView() {
  // 1. 求所有点的外接矩形 minLon/maxLon/minLat/maxLat
  // 2. 按窗口宽高算出比例尺（取两个方向中更紧的那个，保证完整放下）：
  const pad = 0.06
  const s = Math.min(W / (spanLon * (1 + pad * 2)), H / (spanLat * (1 + pad * 2)))
  // 3. 让外接矩形居中：
  view.ox = (minLon + maxLon) / 2 - W / (2 * s)
  view.oy = (minLat + maxLat) / 2 - H / (2 * s)
  fitS.value = s     // 记住初始比例尺，缩放上下限、点的大小都以它为基准
}
```

### 7.5 触屏捏合（彩蛋）

`pointers` 是一个 Map，存着每根手指的实时位置。两根手指按下时记录初始距离，移动时"缩放倍数 = 当前距离 / 初始距离"，锚点取两指中点，其余与 `zoomAt` 同理。代码在 `beginPinch / updatePinch` 里，读懂第 5 节就能读懂它。

## 8. 数据从哪来：fetch + 解析 CSV

### 8.1 为什么放 public/

`public/` 里的文件会被 Vite 原样提供到网站根目录，前端直接 `fetch('track-data.csv')` 就能拿到。数据小（不到 20KB），纯前端解析，无后端服务器——符合本项目的定位。

### 8.2 parseCsv 逐行拆

```js
function parseCsv(text) {
  const lines = text.split(/\r?\n/).filter((l) => l.trim() !== '')  // 按行切（兼容 \r\n），去空行
  const pts = []
  for (let k = 1; k < lines.length; k++) {   // k 从 1 开始 = 跳过表头
    const c = lines[k].split(',')            // 按逗号切列
    if (c.length < 7) continue               // 脏行跳过
    const lon = parseFloat(c[5])             // 第 6 列 = 经度
    const lat = parseFloat(c[6])             // 第 7 列 = 纬度
    if (Number.isFinite(lon) && Number.isFinite(lat)) {
      pts.push({ t: c[0].trim(), lon, lat, lon0: lon, lat0: lat })
    }
  }
  return pts
}
```

`Number.isFinite` 过滤 NaN（`parseFloat` 解析失败会返回 NaN）。

### 8.3 加载与容错

```js
const res = await fetch(import.meta.env.BASE_URL + 'track-data.csv')
```

`import.meta.env.BASE_URL` 是 Vite 提供的部署根路径变量，比写死 `/` 更稳（换部署目录也不出错）。失败时页面中央显示「数据加载失败：…」，不会白屏。

## 9. 生命周期：装上的东西要拆干净

### 9.1 onMounted：页面出现后要做的事

```js
onMounted(() => {
  resize()                    // ① 先量一次画布尺寸
  c.addEventListener('pointerdown', onPointerDown)
  c.addEventListener('pointermove', onPointerMove)
  ...                         // ② 绑定全部交互事件
  c.addEventListener('wheel', onWheel, { passive: false })  // 要 preventDefault 就必须 passive:false
  ro = new ResizeObserver(() => resize())   // ③ 监听窗口尺寸变化
  ro.observe(wrapRef.value)
  loadData()                  // ④ 拉数据 → 解析 → fitView 初始框选
})
```

### 9.2 onBeforeUnmount：离开前拆干净

移除所有事件监听、`ro.disconnect()`、`cancelAnimationFrame(rafId)`——防止组件销毁后还有"幽灵回调"（内存泄漏）。**装了什么就拆什么**，是前端工程师的基本素养。

### 9.3 什么是 ResizeObserver

窗口被拖大拖小时自动回调 `resize()`，重新设置画布分辨率并重画。首次加载数据前尺寸没量好时，它也会补一次 `fitView`。`template ref`（`wrapRef`）就是在这里拿 DOM 的：

```html
<div class="stage" ref="wrapRef">
<script setup>
const wrapRef = ref(null)   // 组件挂载后自动指向那个 div
```

## 11. 新手改造练习

动手改代码是学得最快的方式。改完保存，Vite 会**热更新（HMR）**，页面自动刷新。

1. **换颜色**：把 `C.point` 改成 `#0ea5e9`。
2. **点更大/更小**：`pointRadius()` 里的 `5 * k` 改成 `7 * k`。
3. **允许放得更大**：`sMax()` 里的 `50` 改成 `200`。
4. **平移范围更紧/更松**：`clampView()` 里的 `0.25` 改成 `0.1` 或 `0.5`。
5. **给每个点画序号**：在 drawPoints 里加 `ctx.fillText(String(i), x + r, H - y - r)`（初始缩放时 303 个数字会挤成一团——试试只在 `view.s / fitS.value > 10` 时画，想想为什么）。
6. **悬停时在面板显示选中点信息**：仿照 `scaleText` 写一个新的 computed，读 `hovered` 对应的点。
7. **双击空白恢复视野**：给 canvas 加 `dblclick` 事件，调用 `resetView()`。
8. **换一份数据**：把新的 CSV（保持"经度在第 6 列、纬度在第 7 列"）放到 `public/` 并改名为 `track-data.csv`。
9. **让网格更密**：`drawGrid` 里 `niceStep(90 / view.s)` 的 90 改小。
10. **拖动点时禁止拖出边界**：在拖动的 onPointerMove 里对 `p.lon / p.lat` 用和 clampView 同样的夹逼写法（参考练习 4 的上下界怎么取）。
